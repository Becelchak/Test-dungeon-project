## 🛠 Правила разработки и коммитов

В проекте используется стандарт **Conventional Commits** и семантическое версионирование (**SemVer**).

### Формат сообщения
Каждый коммит должен начинаться с префикса, определяющего характер изменений:

*   `feat:` — Добавление нового функционала (механики, ассеты, UI).
*   `fix:` — Исправление багов и ошибок в логике.
*   `refactor:` — Изменение кода без изменения его поведения (чистка, перенос методов).
*   `style:` — Добавление или обновление визуала, особенно UI элементов. Помимо этого подразумевает правки форматирования, отступов или переименование переменных.
*   `perf:` — Оптимизация производительности (снижение нагрузки, работа с памятью).
*   `docs:` — Обновление документации или комментариев в коде.
*   `chore:` — Технические задачи (настройки проекта, обновление Unity, правка .gitignore).
*   `asset:` — Исключительно для добавления и обновления нетекстовых файлов: 3D-модели, текстуры, аудио, анимации, шрифты.
*   `balance:` — Изменение характеристик без изменения кода. Правка ScriptableObjects, подкрутка урона оружия, радиуса атаки, скорости игрока, частоты спавна комнат.

### Версионность билдов
Проект придерживается формата **MAJOR.MINOR.PATCH** (например, `v1.2.0`):

1.  MAJOR (1.0.0, 2.0.0): Крупная веха разработки. Переход от Прототипа к Вертикальному срезу (Vertical Slice), Альфа-версия, Бета-версия, Релиз.
2.  MINOR (0.3.0 -> 0.4.0): Готовая, работающая крупная система или добавление весомых новых фич (`feat`).
3.  PATCH (0.3.1 -> 0.3.2): Итеративные правки внутри системы.
