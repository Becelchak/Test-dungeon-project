## 🛠 Правила разработки и коммитов

В проекте используется стандарт **Conventional Commits** и семантическое версионирование (**SemVer**).

### Формат сообщения
Каждый коммит должен начинаться с префикса, определяющего характер изменений:

*   `feat:` — Добавление нового функционала (механики, ассеты, UI).
*   `fix:` — Исправление багов и ошибок в логике.
*   `refactor:` — Изменение кода без изменения его поведения (чистка, перенос методов).
*   `style:` — Правки форматирования, отступов или переименование переменных.
*   `perf:` — Оптимизация производительности (снижение нагрузки, работа с памятью).
*   `docs:` — Обновление документации или комментариев в коде.
*   `chore:` — Технические задачи (настройки проекта, обновление Unity, правка .gitignore).

### Версионность билдов
Проект придерживается формата **MAJOR.MINOR.PATCH** (например, `v1.2.0`):

1.  **MAJOR** (1.x.x) — Глобальные изменения или релиз.
2.  **MINOR** (x.1.x) — Добавление новых фич (`feat`).
3.  **PATCH** (x.x.1) — Исправление ошибок (`fix`).
